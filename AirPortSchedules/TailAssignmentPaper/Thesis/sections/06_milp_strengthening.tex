\label{ch:strengthening}

This chapter evaluates formulation-strengthening methods for the integrated
aircraft routing and maintenance model. The corrected ground model and the
corrected split formulation of Constraint~(13) remain the reference model.
The paper-style comparison baseline remains reproducible through explicit
formulation flags. It is distinct from the current application defaults, which
enable sparse aircraft-compatible triggers, day-specific maintenance-state
bounds, and interval-clique overlap rows. Experimental station reachability
and the global-trigger $z/w$ formulation remain opt-in.

\section{Research questions and baseline}

The study asks whether maintenance-trigger preprocessing can reduce model size,
whether interval-specific C13 bounds improve the relaxation, whether stronger
maintenance linking and pairwise conflicts improve exact-solver behaviour, and
whether these effects persist as the fleet and horizon grow.

For comparisons labelled baseline versus strengthened, the baseline is the
explicit paper-style configuration: corrected C13 split formulation, full
aircraft trigger domain, aggregate C8 blocking, and global $M=9{,}999{,}999$.
The current \texttt{MILP\_Sheduler} defaults instead use sparse
aircraft-compatible triggers, day-specific state bounds, and interval-clique
overlap inequalities when overlap constraints are enabled. Reported comparisons
use explicit flags and the same objective, instance, solver backend, and time
budget within each paired experiment. With overlap enabled, the CLI restores
the full-domain, pairwise-overlap comparison baseline using
\texttt{--full-z --no-day-specific-maintenance-bounds --pairwise-overlap}.

\section{Strengthening methods}

\subsection{Aircraft-compatible maintenance domains}

The full-domain comparison baseline creates $z_{ijdc}$ for every
maintenance-eligible flight $i$, aircraft $j$, candidate day $d$, and check
type $c$. The sparse-domain formulation creates this variable only when the
assignment arc $(i,j)$ belongs to the feasible assignment set $X$:
\begin{equation}
 (i,j)\notin X \quad\Longrightarrow\quad z_{ijdc}\text{ is not instantiated}.
\end{equation}
This is a preprocessing reduction. A flight that cannot be assigned to an
aircraft cannot trigger maintenance for that aircraft. This sparse domain is
enabled by default in the current application API; use \texttt{--full-z} to
reproduce the full-domain comparison baseline from the CLI.

\subsection{Deferred-trigger reachability}

The optional reachability filter removes a deferred trigger day when the
station-level timetable test finds an intervening departure from the
maintenance airport after the trigger arrival. Same-day candidates remain
controlled by the detailed C8 window constraints.

This filter is now treated as an experimental domain restriction, not as a
formulation-equivalent preprocessing rule. The station-level test does not know
which aircraft operates each intervening departure and can therefore remove a
day that remains feasible in the joint assignment model. It is disabled in the
certified thesis comparisons.

This differs from the opt-in aircraft-routing reachability presolver. That
presolver follows time-feasible flight connections from each aircraft's initial
airport using assignment-compatible arcs. It removes an assignment arc only
when no no-ferry path can reach that flight. This is a necessary-condition test
for C2--C3, not a proof that the remaining flights can all be covered at once.
If the test would leave any flight without a candidate aircraft, it retains the
original domains and leaves infeasibility detection to the MILP.

\subsection{Strong trigger linking}

For the candidate-day set $D(i,c)$, the strong-link variant adds
\begin{equation}
    \sum_{d\in D(i,c)} z_{ijdc} \leq x_{ij},
    \qquad \forall i,j,c.
    \label{eq:strength_strong_link}
\end{equation}
This removes unsupported fractional trigger mass from the LP relaxation while
preserving the intended integral assignment logic.

\subsection{Interval-specific C13 bounds}

The global C13 constant can be replaced by the valid interval-specific value
\begin{equation}
    M_{jdd'}^c = \max\left\{0,
    \sum_{i\in F_{d,d'}:(i,j)\in X}\tilde{t}_i - T_{\max}^c\right\}.
    \label{eq:strength_tight_m}
\end{equation}
The summation covers every flight compatible with aircraft $j$ in the interval,
so the value is an upper bound on any feasible cumulative flight time. The
pre-horizon C13b rows are unchanged.

\subsection{Pairwise maintenance conflicts}

Aggregate C8 blocking can be disaggregated into
\begin{equation}
    z_{ijdc}+x_{i'j}\leq 1,
    \qquad \forall i'\text{ blocked by the maintenance window of }(i,d,c).
    \label{eq:strength_pairwise_conflict}
\end{equation}
This is at least as strong for the represented blocked-flight set, but it can
increase the row count on large fleets.

\subsection{Interval-clique overlap inequalities}

The supplemental pairwise overlap test can be represented by extended
occupancy intervals $[t_i^{dep},t_i^{arr}+\Delta t)$. Two flights conflict
exactly when their intervals intersect. The clique alternative sweeps interval
start/end events, forms maximal sets of mutually conflicting flights, and adds
one row per aircraft and clique:
\begin{equation}
    \sum_{i\in Q:\,(i,j)\in X}x_{ij}\leq 1,
    \qquad \forall j\in\mathcal{P},\ Q\in\mathcal{Q},
    \label{eq:strength_clique_overlap}
\end{equation}
where $\mathcal{Q}$ is the set of maximal temporal conflict cliques. End events
are processed before starts at equal times, matching the model's rule that a
departure exactly at arrival plus turn time is feasible. Each clique inequality
is valid and covers its constituent pairwise conflicts; the pairwise
formulation is available with \texttt{--pairwise-overlap}. Clique overlap is
the current default whenever overlap constraints are enabled; it can also be
selected explicitly with \texttt{--clique-overlap}.

A bounded comparison over M-20, L-30, and X-40 found 292 maximal temporal
cliques covering all 7,641 M-20 pairwise conflicts. Under a common 20-second
Gurobi limit and the same validated path-cover start, clique rows reduced the
full model's constraint count by 86.2\%, 91.3\%, and 93.4\%, respectively.
Build time also fell by approximately 32\%, 32\%, and 42\%. The incumbent
values were unchanged for M-20 and L-30; pairwise overlap found a slightly
better X-40 incumbent in this short run. None of the six runs proved
optimality, so these data support a model-size and build-time improvement, not
a general solve-time claim. Raw solver duals below the analytical
assignment-cost floor are rejected; the table reports the valid floor instead.

A separate 25-second M-20 probe produced a lower clique incumbent than its
pairwise counterpart, but that result is not used in the fixed-budget table
because its time limit differs. Together, the bounded runs support clique
overlap as the current default for its substantial row-count and build-time
reductions, not as a claim of uniformly better incumbent quality or solve time.
The pairwise option remains available for controlled comparisons.

\section{Combined formulation and implementation updates}

The combined experimental variant enables sparse aircraft-compatible domains,
optional reachability filtering, strong trigger linking, interval-specific C13
bounds, and pairwise maintenance conflicts. The certified results below use
sparse domains and tight C13 bounds, but disable reachability.

The main MILP API exposes \texttt{--sparse-z},
\texttt{--day-specific-maintenance-bounds},
\texttt{--aircraft-routing-reachability}, and \texttt{--tight-c13-m}. Sparse
triggers and day-specific bounds are enabled by default; aircraft-routing
reachability and tight C13-M remain opt-in. The day-specific bounds fix
$y_{jdc}$ to zero when the instantiated trigger set has
no member for that aircraft/check/day, and similarly fix hierarchy states
$\mathit{mega}_{jdc}$ when none of their covering checks can occur. Empty C11
trigger-link rows and redundant hierarchy/one-check rows are omitted when these
bounds make them tautologies. These bounds are derived from the actual $z$
domain and do not impose an arbitrary calendar window.

On the M-20 30-day integrated build, enabling sparse triggers, day-state bounds,
aircraft-specific routing reachability, and tight C13-M reduced variables from
147{,}620 to 139{,}363, constraints from 313{,}740 to 293{,}224, and $z$
variables from 123{,}620 to 116{,}327. Build time was similar (27.6 versus
28.9 seconds), so the measured benefit is a smaller solver model, not faster
Python construction. On the curated ABCD case, the same safe options preserved
the optimal objective at 9{,}600 while reducing $z$ from 220 to 44.

Several implementation changes also improve correctness and scalability:
\begin{enumerate}
    \item The corrected split C13 formulation remains the default.
    \item Deferred C8 blocking prevents an aircraft from escaping before a
    selected maintenance day without blocking every departure on the whole
    selected day. This avoids the previous over-constraint when hierarchy and
    deferred triggers interact.
    \item A/B trigger domains use a conservative three-day default deferral cap;
    an explicit option allows wider experimental domains. The cap is reported
    because it changes the candidate domain.
    \item Effective trigger-day and trigger-flight indexes are cached during
    model construction. The reported $z$ count is the actual instantiated
    Pyomo domain after sparse filtering.
    \item The Step 4 harness performs a non-ferry C2--C3 routing preflight,
    skips instances proven routing-infeasible, and records optimal, time-limit,
    aborted, and error outcomes separately. A non-finite bound is reported as
    unavailable rather than as a numerical lower bound.
\end{enumerate}

The C10 builder also skips empty station-day expressions instead of passing a
trivial Boolean to Pyomo. This is a construction-robustness correction and does
not alter any nonempty capacity constraint.

\section{Correctness and implementation checks}

The explicitly discovered test suite verifies the configured defaults and
their explicit alternatives, sparse assignment arcs, trigger-domain
construction, interval-specific $M$ values, pairwise conflict rows,
solver-status handling, CSV provenance, and the skip-and-continue behaviour
for routing-infeasible instances. Additional tests check zero-based cost-row
mapping, aircraft-specific routing starts, day-state bounds, and overlap-clique
coverage. Test counts are reported by the test run rather than fixed here.

Structural tests are necessary but not sufficient. The performance comparison
therefore checks that baseline and optimized configurations preserve the same
objective on feasible instances.

\section{Bounding framework}

The problem is a minimisation problem. Its optimum is bracketed by a lower
bound and an upper bound. The LP relaxation value is a valid lower bound on any
integer-feasible schedule. During branch and bound, the solver also reports a
dual bound. Any feasible incumbent is an upper bound. A heuristic cost is an
upper bound only when it covers every flight; partial schedules are reported
but excluded from the bracket.

For a dual bound $\underline{z}$ and incumbent $\bar z$, the residual gap is
\begin{equation}
    \gamma = \frac{\bar z-\underline{z}}{|\bar z|}.
    \label{eq:strength_gap}
\end{equation}
A time-limited run without a finite bound or incumbent is reported as
bound-unavailable, not as an artificial large gap.

\section{Benchmark design}

Three tiers separate compactness, solved bound evidence, and scalability:
\begin{description}
    \item[Small] 20 constructive A-check instances with 64 flights and 8
    aircraft. Both formulations solve every instance.
    \item[Medium] Five certified full-hierarchy instances with 128 flights and
    8 aircraft. Both formulations solve every instance.
    \item[Large] Build-only scaling instances with 320 flights and 20 aircraft,
    and 560 flights and 8 aircraft. These establish model-size behaviour but do
    not provide paired exact-solve runtimes for the 560-flight cases.
\end{description}

All certified comparisons use the HiGHS backend and identical per-run budgets.
The separate large-tier scaling table is generated from the build-only CSV.
Cost lookup maps flight identifiers to their rows in the input flight array,
so both zero-based and one-based identifier conventions are handled without
shifting the cost matrix.

\section{Larger-model statistics}

The large build-only scaling data show that the trigger-domain reduction grows
with horizon and fleet structure. For the 320-flight cases, $z$ variables fall
by $58.1\%$, while pairwise conflict rows increase the constraint count by
approximately $23$--$26\%$. For the 560-flight cases, $z$ variables fall by
$86.3\%$ and the constraint count falls by approximately $59.6\%$.

\section{Interpretation and limitations}

The evidence supports a narrower claim than uniform improvement. The compactness
result is robust: sparse aircraft-compatible domains remove unsupported trigger
variables, and the reduction grows with the trigger domain. The LP-bound result
is conditional: the tested Small and Medium relaxations are already integral or
near-integral, so the strengthening does not tighten their objective values.

For larger configurations, the relevant question is what can be built and
solved within a fixed budget. Pairwise conflicts can increase the constraint
matrix on large fleets even while reducing the integer trigger domain. The
current artifacts support model-size claims for the Large tier, but not paired
exact-runtime claims for the 560-flight cases.

The heuristic upper-bound side remains limited because the constructive
heuristics do not cover every flight in these experiments. Their costs are
therefore not treated as valid upper bounds. Finally, the results are limited
to the declared tiers, backend, budgets, and non-ferry routing semantics.
