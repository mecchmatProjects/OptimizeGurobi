# fore-benchgen v2 certified benchmark data

This directory contains versioned synthetic benchmark instances generated by
`src/fore_benchgen.py`. It is a complementary test family; it does not replace
Khaled-style, curated, or existing constructive instances.

## Validation family

`validation/` contains five deterministic `sma1` replicates generated with:

- `preset=sma1` (`P=8`, `H=8`)
- `topology=euler`
- `threshold_mode=coprime`
- `cost_model=factor`
- `application_compatible=true`
- generator version `2.0.0`
- root seed `20260814`

Each replicate contains an instance JSON file, a planted reference certificate,
a generator validation report, and an SHA-256 manifest. The application-
compatible profile enforces the shared no-ferry contract: one-based flight IDs,
the declared minimum turn time, single-day maintenance durations, and
post-arrival maintenance events.

Before a file is admitted to this directory, its certificate must pass both the
generator validator and `verify_milp_certificate` against every active Pyomo
constraint in the corrected MILP.

## Pilot results

`results/tables/fore_benchgen_v2_validation_milp_pilot.csv` records a matched
HiGHS pilot using a 60-second per-instance limit. All five validation instances
were solved to optimality. This pilot verifies the data-to-application path; it
is not a replicated performance study and must not be used for statistical or
general performance claims.

`pilot_grid/` extends this work to ten pre-specified full-hierarchy instances:
five `sma1` cases (`P=8`, `H=8`) and five `sma2` cases (`P=8`, `H=21`), all
generated from `experiments/configs/fore_benchgen_v2_pilot_grid.json`. Every
published certificate passed the fixed-variable corrected-MILP verification.
The five `sma2` HiGHS pilot solves were all optimal, with observed elapsed times
from 53.78 to 73.81 seconds. The configured limit was 60 seconds; actual times
are retained as recorded evidence and should not be silently truncated.

Use `experiments/run_fore_benchgen_benchmark.py` to create additional matched
runs. Results must retain the generator version, seed, topology, threshold mode,
cost model, compatibility flag, and certificate-validation fields.
