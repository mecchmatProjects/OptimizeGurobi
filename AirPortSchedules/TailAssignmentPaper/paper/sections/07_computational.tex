\paragraph{Evidence versions.}
The tables below dated 2026-10-20 are preserved historical experiments with
nonuniform maintenance policies. They are not results for the uniform
flexible encodings of \Cref{subsec:uniform_flexible}. In particular, their
strict interval/prefix ablation is a day-boundary comparison; its opening-row
implementation omitted the first day. Those historical LP bounds are not
evidence for the repaired formulation; the fresh rerun is reported in
Table~\ref{tab:repaired_prefix} above.

\subsection{Implementation and environment}

All models are implemented in Python using Pyomo. The reported exact solves
use unrestricted IBM ILOG CPLEX~12.6 for AMPL through Pyomo's
\texttt{cplexamp} interface. The deterministic instance generator and all
benchmark scripts are included in the companion repository. The generator
independently validates each designated seeded rotation with its maintenance
counter; MILP objectives and statuses are taken from the solver runs.

We also smoke-tested the Pyomo interface with Gurobi~11.0.3 on small feasible
and infeasible models. On Windows, the \texttt{gurobi} shell interface runs
through the Python interpreter bundled with Gurobi (discovered from
\texttt{GUROBI\_HOME}), rather than through
\texttt{gurobi\_cl.exe}. The infeasible case returns no incumbent and marks
its problem bounds unavailable; the implementation preserves that
termination status and omits schedule extraction. This is an interface check,
not a benchmark comparison: all computational results and timing tables in
this paper use CPLEX.

\subsection{Cumulative-flight-time row verification}

The original C13 row, its endpoint-split alternative, and the legacy opening
companion were evaluated on the hand-built four-day counterexample
\path{data/instances/c13_loophole_test.json}. The instance fixes one
aircraft, $T^A_{\max}=600$ minutes, $M_{14}=1200$ minutes, 1,200 minutes of
flying in $(1,4]$, and two check patterns: checks at both endpoints, and a
check only at the end. The table reports the C13-family result and, for exact
state methods, the corresponding hour-state result; it is not a test of every
other model constraint. With both endpoints checked, C13 is active and the
split rows are relaxed. With only the ending check, C13 is inactive by design;
the legacy opening companion is separately tested for whether it protects
pre-check exposure. The exact state formulations reject both overdue
schedules. Thus, the both-endpoints case is a counterexample to the split,
whereas the one-endpoint case illustrates why a practical model needs a
separate opening-hour condition, not why C13 should be active without two
checked endpoints. The results test
\Cref{subsec:c13_opening_coverage,subsec:c11_corrected}.

\subsection{Historical five-method type-A comparison}
\label{subsec:event_measurements}

The ordered implementation removes explicit successor variables and propagates
an aircraft-local prefix state through flights sorted by departure time. A
maintenance event is attached to its triggering flight, and the pre-check row
prevents an event from repairing an already overdue arrival. The five methods
evaluated in the matched A-only experiment are the original Khaled row,
the endpoint split, the strengthened corrected legacy rows, the optimized
ordered event-based formulation, and its flexible-start variant.
Their builder identifiers are respectively
\path{legacy_paper_c13}, \path{legacy_endpoint_split},
\path{legacy_corrected_strengthened}, \path{event_based_optimized}, and
\path{event_based_flex}. A result is described
as objective-matched only when both
compared methods are optimal. The legacy methods use a zero-day trigger-to-check
deferral cap in the matched rerun; the optimized event model starts maintenance
after the triggering flight, while the flexible event model permits a
one-day (1440-minute) offset. The day-indexed and event-based timing rules
remain different, so this setting improves comparability but does not make the
formulations identical.

\subsection{Summary and limitations}

All 30 solver runs returned incumbents and 26 terminated optimally. The four
time-limited Event-based runs are the P=15 cases at H=30 and H=49; their
incumbents are not optimality certificates and are excluded from paired timing
averages. Independent replay reports zero violations for all six strengthened
legacy schedules and the four optimal schedules from each Event-based method.
The original-paper and endpoint-split schedules fail replay in all six cells,
consistent with the C13 counterexamples above. Time-limited Event-based
schedules were not replayed.

The experiment uses one deterministic seed per $(P,H)$ cell, one
maintenance-capable hub, A checks only, and a single CPLEX configuration. It
should be read as a reproducible scale-up test, not broad statistical evidence.
Follow-up validation should cover multiple seeds, varied airport networks and
station capacities, nonzero initial flight-hour counters, and independent
schedule replay for each formulation. Solver comparisons should vary presolve
and warm-start settings and report optimality gaps and memory alongside the
metrics collected here.

\subsubsection{Cumulative-prefix LP and MILP ablation}
\label{subsec:hour_prefix_ablation}

We compared the compact strict interval formulation with an opt-in cumulative
daily-prefix representation on the four P=5/10 instances. Both use the same
strict C13/C13b conditions, zero-day legacy deferral, and bound-preserving LP
relaxation. All interval and prefix LPs and MILPs terminated optimally on these
four cases. The prefix projection reproduces the interval LP objective to
numerical precision, as expected from the telescoping reformulation in
\Cref{subsec:c13_prefix_equivalence}, and the two formulations return identical integer
objectives. The exact day-state model has a stronger LP bound on all four
instances, so prefix-versus-interval equivalence should not be misread as
equivalence to that stronger relaxation. The P=15 LP ablation is excluded:
several solver runs reached their iteration limit and returned no reliable LP
objective.

\subsubsection{Conditional removal of unnecessary A checks}

We also tested the sufficient pruning condition that removes optional A-check
triggers when a tail's initial exposure plus all assignable flight hours is
below the A threshold. On a modified six-flight A-only control, each tail had
at most 20 assignable flight hours and zero initial exposure, versus a
100{,}000-minute threshold (1{,}666.7 hours). The unpruned and pruned models
both solved optimally at objective 600 and passed independent replay. Pruning
removed all 12 trigger variables and reduced the model from 88 to 76 variables
and from 187 to 172 constraints. This is a construction/model-size check on a
deliberately qualifying instance; it does not establish a runtime improvement
on operationally binding cases. Table~\ref{tab:a_check_pruning} summarizes the
run; the run and transformed-input hashes are

\subsubsection{Independent schedule replay and scope}

The generator replay certifies the designated rotations; the separate
post-solve replay audits optimizer-selected schedules. For legacy models it
resets the hour counter after the selected maintenance day; for ordered event
models it resets after the selected trigger flight and independently checks
event timing, flight blocking, and station capacity. This protocol detects
violations in the paper and split C13 variants and returns zero violations for
the strengthened exact-state and optimal Event-based schedules in this suite.
It does not certify the four Event-based incumbents stopped by the time limit.

\subsubsection{Event-model comparison}

Optimized and flexible Event-based objectives match the strengthened legacy
optimum on the four jointly optimal P=5/10 cells. At P=15, both event methods
return the same incumbent as strengthened legacy, but neither proves
optimality at either horizon. No objective-equivalence claim is made beyond
these matched cases.

\subsubsection{Flexible-start Event-based variant}

The flexible-start implementation uses the integer-grid E14--E21 formulation
with a one-day deferral window, as described in
\Cref{subsec:flex_complexity}. Its model has more variables and constraints
than the immediate-start event model in each generated performance cell. The
objective comparison above is limited to solver results and does not replace
independent schedule validation.





\label{subsec:robustness}



The scale-up experiment uses one deterministic seed per $(P,H)$ cell, one
maintenance hub, A checks only, and a single CPLEX configuration. It is a
reproducible instance-family comparison, not broad statistical evidence.
Multiple seeds, varied airport networks and station capacities, and solver
configuration sensitivity remain important follow-up experiments.
