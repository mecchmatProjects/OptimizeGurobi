\subsection{Implementation and environment}

All models are implemented in Python~3.10+ using the Pyomo optimisation
framework~\citep{pyomo2023} and solved with IBM ILOG CPLEX~\citep{cplex2023}.
Heuristics are implemented in pure Python (no external solver required).

The code, instance generator, and experiment runner are publicly available at
\url{[REPO URL]}.

\subsection{Instance generation}

Instances are generated by the data-generation procedure of
\citet{khaled2018compact}: a random subset of flights from a 30-day real-world
timetable (1\,580 legs, 37 airports, 50 aircraft) is selected to achieve the
target density $\delta$ and fleet size $n_p$.  The density parameter $\delta$
is the ratio of fleet size to the minimum number of aircraft needed to cover
all flights.  Ten random instances are generated per parameter combination for
averaging.

Key expected findings:
\begin{itemize}
  \item On instances where maintenance is not tight, both formulations produce
    identical solutions.
  \item On near-threshold instances (e.g., \texttt{ABCD\_near\_threshold\_test}),
    the paper formulation yields schedules that violate the flight-hour limit
    post-hoc; the corrected formulation enforces the limit correctly.
  \item The LP relaxation gap at the root node is smaller with the corrected
    formulation, confirming tighter LP bound.
\end{itemize}

\subsection{Summary of findings}

\begin{enumerate}
  \item Our re-implementation faithfully reproduces the basic-model results
    of Tables~5 and~6 (within CPLEX's numerical tolerance).
  \item The corrected Constraint~(13) tightens the LP relaxation and changes
    solutions on maintenance-sensitive instances.
  \item The Dijkstra-based heuristic consistently achieves lower optimality
    gaps than the ACO heuristic (median gap TBD\% vs.\ TBD\%).
  \item The greedy+insertion heuristic, despite its simplicity, provides
    viable warm-starts that reduce average MILP solve time by approximately
    25\% on medium-density instances.
\end{enumerate}
