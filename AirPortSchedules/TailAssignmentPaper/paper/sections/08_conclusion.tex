\section{Conclusions and Future Work}
\label{sec:conclusion}
%%==========================================================================

This paper revisited the compact Tail Assignment Problem model of
\citet{khaled2018compact}, making three concrete contributions.

\paragraph{C2--C4 feasibility correction.}
We showed that the basic balance constraints can admit a simultaneous-
departure corner case that is mathematically feasible but operationally
impossible.  Adding explicit pairwise non-overlap constraints restores
physical executability without altering the variable set of the compact model.
This correction also clarifies the domain on which maintenance constraints are
evaluated.

\paragraph{Constraint~(13) correction.}
We proved that the original cumulative-flight-time constraint can leave the
opening maintenance interval unbounded. We then showed that the natural
two-row endpoint split is also insufficient: it can miss flying time between
consecutive check nights. The exact replacement uses a continuous daily
cumulative state with maintenance-triggered resets and explicit initial
conditions. The legacy computational runs use the endpoint split and therefore
do not certify the exact between-check bound.

\paragraph{Effect on C8--C14.}
The non-overlap correction changes the assignment domain on which C8--C14
operate but does not repair cumulative-hour propagation by itself.
\Cref{thm:physical_feasibility_c1_c14} therefore relies specifically on the
exact state constraints, together with the corrected basic feasibility and
maintenance-event constraints.

\paragraph{Full $\{A,B,C,D\}$ hierarchy.}
We extended the single-type framework to an explicit four-level A/B/C/D
hierarchy. Effective-check indicators encode heavier-check resets, separate
start and occupancy variables represent multi-day C/D checks, and initial
hour/day values carry maintenance history into the horizon. The extension adds
$O(n_pn_d|\C|)$ state and event structure plus sparse flight-exclusion rows;
its solve-time multiplier has not yet been established empirically.

\paragraph{Reproducibility.}
The project contains the code, deterministic instance generator, experiment
configurations, and result tables needed to rerun the reported snapshots. The
legacy split formulation and the separate event/state formulation are retained
as distinct implementations so their future performance can be compared
without conflating their maintenance semantics.

\paragraph{Threats to validity.}
The reported computational comparisons are intentionally scoped to
the synthetic benchmark family used in this study. The quick grids use few
instances, several dense runs end in infeasible/error states, and no completed
paper-versus-split-versus-exact C13 experiment is reported. Performance
conclusions are therefore descriptive of these runs only. Decomposition-heavy
and robust/scenario alternatives may exhibit different trade-offs under their
native assumptions and tuning protocols.

\subsection*{Future directions}

\begin{itemize}
  \item \textbf{Integrated fleet assignment and routing:} the compact model
    is well-suited for integration with fleet-assignment decisions, as noted
    by \citet{khaled2018compact}.  The absence of the cyclic constraint
    facilitates this integration.
  \item \textbf{Robust and recoverable variants:} extending
    \citet{borndorfer2010robust, froyland2013recoverable} to the compact
    formulation with full maintenance hierarchy is an open problem.
  \item \textbf{Controlled formulation benchmark:} implement separately
    selectable paper-C13, endpoint-split, and exact-state builders, validate
    every solution by replaying its maintenance counters, and compare model
    size, relaxation bounds, runtime, and feasibility on identical instances.
  \item \textbf{Heuristic and metaheuristic methods:} constructive and
    learning-based heuristics for the corrected, full-hierarchy model are
    deliberately out of scope here and are left for a companion study.
\end{itemize}
