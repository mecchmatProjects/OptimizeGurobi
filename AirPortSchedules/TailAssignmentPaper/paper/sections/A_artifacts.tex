\section{Artifact index}
\label{app:artifacts}
%%==========================================================================

All instances, model code, drivers, raw result tables, saved schedules and
provenance sidecars (input hashes, solver configuration, source snapshots) are
part of the replication package. \Cref{tab:artifacts} maps each experiment of
\Cref{sec:computational} to its inputs and raw outputs. CPLEX and non-Gurobi
results are in \path{results/tables/}; Gurobi CSVs, schedules, source snapshots
and metadata are in \path{gurobi_results/}. Result files carry the suffix
\path{.metadata.json} (provenance) and \path{.schedules.json} (saved decisions)
where applicable; drivers are in \path{experiments/}.

The complete Gurobi folder contains older branch-compatible artifacts and
20261119 refreshes. CSV and sidecar hashes validate for all 22 metadata records.
Only the A-only 20/30-aircraft, 40/50-aircraft, uniform-large and ten-seed batches
match 64 distinct current-branch input hashes and support the quantitative
Gurobi claims. The other records reference 66 distinct missing JSON hashes.
The five-method Gurobi table is therefore retained as an archival diagnostic,
not as an input-matched CPLEX comparison. The machine-readable exception list
is \path{gurobi_results/provenance_audit.json}; rerunning every supplied
Gurobi batch requires restoring those exact JSON bytes.
